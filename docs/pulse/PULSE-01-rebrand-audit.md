# PULSE — Product Rebranding Audit

**Status:** Draft for review · **Date:** 2026-10-26 · **Target identity:** **PULSE — API & Data Reliability Intelligence** · **Tagline:** *Trust Every Flow.*

This audit lists every old-identity reference found in the repository, grouped by risk, with the
intended PULSE replacement. It is deliberately **not** a global search-and-replace script: several
references are runtime identifiers where a blind rename breaks running systems.

**Evidence base:** case-insensitive scan for `ryme` across all 191 tracked files →
**190 matches in 75 tracked files** `[RUN]`, plus a terminology scan for deployment-platform
language `[RUN]`. Line numbers refer to the working tree at 2026-10-26.

> Scope note: per the execution boundary for this pass, **no branding changes have been applied yet.**
> This document is the change list; each risk tier has its own approval gate (see
> `PULSE-05-decisions-for-approval.md`).

---

## 1. Risk tiers

| Tier | Meaning | Gate |
| --- | --- | --- |
| **T1 — Cosmetic** | Docs, comments, labels, test titles. No runtime effect. | Safe to apply once D1 (brand name) is approved |
| **T2 — User-visible** | UI text, page title, favicon, taglines, README positioning. | D1 + D2 (terminology map) |
| **T3 — Runtime identifiers** | Package names, log service names, storage keys, Docker labels/names, env values. | D3 (identifier rename plan) — coordinated change |
| **T4 — External/irreversible** | Git remote, repository name, public metadata, commit history. | D7 — explicit authorization, never automated |

## 6. Recommended application order

1. **Wave A (T1 cosmetic)** — docs/comments/scripts/test titles. Revertible, zero runtime risk.
2. **Wave B (T2 user-visible)** — index.html, Layout, Login, Dashboard, README rewrite, favicon asset.
   Requires approved terminology map (D2) so we don't re-do copy twice.
3. **Wave C (T3 runtime identifiers)** — one atomic commit per identifier group (I1–I9), each gated by
   `pnpm typecheck` + `pnpm build`, with compose recreate instructions in the commit message.
4. **Wave D (T4 external)** — only with explicit authorization; separate session, documented.

**Regression gate for every wave:** `pnpm typecheck` (PASS baseline), `pnpm build` (PASS baseline),
`npx tsx --env-file=../../.env test-e2e.mjs` (PASS baseline). `pnpm lint` currently FAILS and must be
fixed first (file #2 in the change-first list) so it can serve as a gate.
