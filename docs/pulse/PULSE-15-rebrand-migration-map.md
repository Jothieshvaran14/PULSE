## 4. Retained historical audit evidence (Class G — deliberate)

All `docs/pulse/PULSE-00 … PULSE-13` records keep their legacy references **unedited** (except the two additive status rows updated in earlier phases and the PULSE-07 status column this phase). They are dated audit/decision evidence: describing what existed at audit time is their function — rewriting them would falsify the record. Affected files: `PULSE-00` (11), `PULSE-01` (41 — it *is* the legacy change list), `PULSE-02` (1), `PULSE-03` (3), `PULSE-04` (2), `PULSE-05` (4), `PULSE-06` (2), `PULSE-07` (5), `PULSE-08` (1), `PULSE-09` (4), `PULSE-10` (4), `PULSE-11` (7), `PULSE-12` (2), `PULSE-13` (7). ## 5. Compatibility summary (what a future operator must know)

1. **No API route, DB table, DB name/user, or env-var name changes in Phase 1** — existing integrations, `.env` files, and the live database are unaffected.
2. **Storage key rename (C2):** logged-in browser sessions log out once.
3. **Package rename (C1):** any external script calling `pnpm --filter @ryme/…` must switch to `@pulse/…`; the lockfile importer keys change in the same commit. `packageManager` and all scripts otherwise identical.
4. **Docker names unchanged (deferred):** `docker compose` workflows, `DOCKER_NETWORK`, container names, and running containers behave exactly as before Phase 1. Their migration steps are staged in §3.3 for the future approved pass.
5. **SEC-23/24 config changes** (separate security commit): after `docker compose up -d`, Postgres listens on loopback only, and Traefik's unauthenticated dashboard API is disabled (running container already had no host 8080 mapping). Re-apply with `pnpm infra:up`.
6. **Deferred rollback files:** remain uncommitted and unwired; the plan lives in `PULSE-14` §4.
